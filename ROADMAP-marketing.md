# EventApp — Marketing Roadmap (MVP Launch)

> **Goal:** Launch in 7 Polish cities, acquire 200 claimed venues, 1,000+ events on the map, and first active organizers within 3 months of starting development. This roadmap covers only the MVP phase — getting first customers (both B2C users and B2B organizers).

> **Two-sided marketplace:** EventApp must acquire both supply (venues/organizers) and demand (event-goers) simultaneously. Supply-side activation is the primary constraint — without active venues publishing events, there's nothing for users to discover.

---

## Target Audiences

### B2C — Event-Goers (Demand Side)

| Segment | Description | Primary Channel |
|---------|------------|-----------------|
| Urban explorers (18-35) | Active lifestyle, looking for things to do tonight/this weekend | Instagram, TikTok, app stores |
| Culture enthusiasts (25-45) | Theater, galleries, concerts — regular attendees | Facebook groups, local media |
| Newcomers / tourists | New to a city, looking for local events | Google Search (SEO), travel blogs |
| Students (18-25) | Budget-conscious, high frequency, social sharing | University channels, word-of-mouth |

### B2B — Venue Owners/Organizers (Supply Side)

| Segment | Description | Approach |
|---------|------------|----------|
| Small venue owners | Bars, clubs, cafes with regular events | Direct outreach, personal calls |
| Cultural institutions | Theaters, galleries, museums | Partnership proposals |
| Event organizers | Independent promoters, festival organizers | Industry meetups, referrals |
| Co-working spaces | Business events, meetups, workshops | Cold email + LinkedIn |

## Phase 1 — Supply-Side Activation (Week 7-10, overlaps with development Week 7-10)

> **Critical:** Without venues publishing events, there's nothing to market. Supply-side must be activated before or simultaneously with demand-side launch.

### 1.1 Poznan — Primary Launch City

> Poznan first (densest event scene, founder's network advantage). Other cities follow 1-2 weeks after.

- [ ] P0 **Personal outreach to top 50 venues in Poznan:**
  - Phone calls to top 10 (highest priority — direct relationship building)
  - Personalized emails to next 20
  - LinkedIn/Instagram DMs to remaining 20
  - In-person visits to 5-10 key venues (bars, clubs with the most events)
- [ ] P0 **"Founding Partner" positioning:**
  - First 50 claimed venues get "Founding Partner" badge on their profile (permanent)
  - Featured placement in-app during first month
  - Priority support (direct WhatsApp/phone line to founder)
  - Offer to help create their first 3 events (white-glove onboarding)
- [ ] P0 **On-site demo sessions:**
  - Visit venues during off-hours (Mon-Wed afternoons)
  - Show the dashboard on their own phone/laptop
  - Walk through: claim profile -> add photo -> create event -> see it on map
  - Leave behind one-pager with QR code to dashboard
- [ ] P0 **Follow-up cadence:**
  - Day 1: Initial contact (call/email/DM)
  - Day 3: Follow-up if no response
  - Day 7: Second follow-up with "X venues in your area have already claimed"
  - Day 14: Final attempt with social proof ("join 30+ venues already on EventApp")

### 1.2 Expansion to Other 6 Cities

- [ ] P0 **Replicate Poznan playbook** for Warsaw, Krakow, Wroclaw, Gdansk, Katowice, Lodz:
  - Identify top 30 venues per city (scale down from 50 since less founder network)
  - Email + DM outreach (no in-person for non-local cities in MVP)
  - Virtual demo via screen share for interested venues
- [ ] P1 **City ambassadors** — recruit 1 local contact per city:
  - Eventful person (nightlife blogger, local influencer, venue staff member)
  - Task: spread the word to venues, report back on local event scene
  - Incentive: featured "Ambassador" profile, early access, potential paid role post-launch

### 1.3 Aggregation as Supply Bootstrapping

> The aggregation pipeline (backend Phase 0.3) fills the map before organizers claim venues — critical for the "full map" perception.

- [ ] P0 **Verify aggregation coverage:**
  - >= 1,000 events across 7 cities before public launch
  - At least 100 events per major city (Warsaw, Krakow, Wroclaw)
  - At least 50 events per smaller city (Gdansk, Katowice, Lodz, Poznan supplemented by native)
  - Zero-result searches < 10% for top queries per city
- [ ] P0 **Content quality check:**
  - No duplicate events visible on map
  - Event photos present for >50% of events (placeholder for rest)
  - All events have valid dates (no past events showing)
  - Categories correctly assigned

## Phase 3 — Retention & Growth (Week 12 — Month 3)

### 3.1 Activation Metrics Tracking

| Metric | Target | Action if Below Target |
|--------|--------|----------------------|
| D1 app opens (after install) | > 70% | Improve onboarding, push notification timing |
| "Allow location" permission rate | > 60% | Better pre-permission screen copy |
| First event viewed (within session 1) | > 50% | Improve map density, reduce time-to-first-pin |
| First venue followed (within 7 days) | > 20% | Better follow CTAs, featured venue prompts |
| Push notification opt-in | > 50% | Improve permission timing (on first follow) |
| D7 retention | > 30% | Content quality, push strategy, notification cadence |
| D30 retention | > 20% | Weekly value (digest), event reminders |

### 3.2 Push Notification Strategy (Retention Engine)

> Push is the #1 retention lever. Optimize for opens without causing fatigue.

- [ ] P0 **Venue push (organizer-triggered):**
  - Organizer sends "New event: [Name] this Friday!" -> delivered to all followers
  - Max 1/day/venue — prevents spam
  - Deep links to event detail
- [ ] P1 **System push notifications (automated):**
  - "Weekend Digest" — Friday 16:00, personalized: "12 events this weekend near you"
  - "Event reminder" — 2 hours before saved event starts
  - "New events from [Followed Venue]" — triggered when venue publishes
- [ ] P1 **Push notification A/B testing:**
  - Test timing (morning vs afternoon vs evening)
  - Test copy style (casual vs informative)
  - Optimize for open rate while keeping opt-out < 15%

### 3.3 Content Marketing (Ongoing)

- [ ] P0 **Weekly "This Weekend" posts** on Instagram + Facebook (per city):
  - Curated 5-8 events, visual carousel format
  - Posted Thursday evening or Friday morning
  - Tags/mentions of featured venues (incentivizes venues to share)
- [ ] P1 **Venue spotlight series** — Instagram story / Reel featuring a claimed venue:
  - Interview with owner (30-60 second video)
  - "Follow them on EventApp to get notified about their events"
  - 1-2 per week across all cities
- [ ] P1 **User-generated content:**
  - Encourage users to share events they discover ("Found this on @eventapp_pl")
  - Repost stories/photos from events discovered through the app
  - Instagram "Share to Stories" CTA after attending an event
- [ ] P1 **TikTok content:**
  - "Things to do in [city] today" — trending format
  - Event highlights / venue walkthrough (15-30 seconds)
  - 3-5 posts per week, prioritize trending sounds/formats

### 3.4 Community Building

- [ ] P1 **Facebook Groups:**
  - "EventApp [City]" group per launch city for event recommendations
  - Moderate and seed with content initially
  - Goal: organic event sharing between users
- [ ] P1 **WhatsApp Broadcast lists** (opt-in):
  - Weekly event roundup per city
  - Low-friction sharing (WhatsApp dominant in Poland)
- [ ] P2 **Event meet-ups:**
  - Organize "EventApp Networking Night" in Poznan (Month 2)
  - Invite claimed venues + power users
  - Content opportunity (photos, testimonials)

### 3.5 Community Scout Growth Loop

> Users who submit event tips become invested in the platform. Their "Tipped by @username" attribution is shareable, and scout badges create status-driven engagement.

- [ ] P0 **Promote event tip submission in-app:**
  - "Know about an event we don't have? Tell us!" — prominent CTA on map screen
  - Post-submission confirmation: "Thanks! You're helping your city discover more events."
- [ ] P0 **Scout attribution as viral loop:**
  - "Tipped by @username" visible on published events — scouts share "their" events with friends
  - When shared via social/WhatsApp, attribution is visible on the web B2C event page too
- [ ] P1 **Scout leaderboard promotion (post-launch):**
  - Monthly "Top Scouts in [city]" social media post — recognizes top contributors
  - In-app leaderboard showing top scouts per city (P1 feature — backend + mobile)
- [ ] P1 **Scout recruitment messaging:**
  - Target users who follow many venues but haven't submitted tips: "You know the scene — help others discover events!"
  - Onboarding email after first follow: "Know about an event? Submit a tip and earn Scout status"

### 3.6 Referral & Virality

- [ ] P1 **Share incentives:**
  - "Share EventApp with 5 friends" — no reward needed initially (validate natural virality first)
  - Track viral coefficient: shares per user, installs per share
- [ ] P1 **Deep links for sharing:**
  - When users share an event, the link opens web B2C page with smart banner -> app install
  - Track installs from shared links (attribution)
- [ ] P2 **Referral program (if organic K-factor < 0.3):**
  - "Invite a friend, both get [reward]" — define reward only if natural sharing is insufficient
  - Potential rewards: early access to features, featured profile badge

### 3.7 B2B Retention (Organizer Engagement)

- [ ] P0 **Onboarding follow-up sequence:**
  - Day 1 after claim: "Welcome! Here's how to add your first event" (email)
  - Day 3: "Add a photo to your profile — venues with photos get 3x more views" (email)
  - Day 7: "You have X followers! Send your first push notification" (email)
  - Day 14: "Your events were viewed X times this week" (weekly report email)
- [ ] P0 **Weekly performance email to organizers:**
  - "Your venue this week: X views, X new followers, X event views"
  - Comparison to previous week (growth indicators)
  - CTA: "Publish your next event" or "Send a push to your followers"
- [ ] P1 **Success stories:**
  - Document early wins: "Venue X gained 50 followers in 2 weeks"
  - Share as social proof in outreach to new venues
  - Post on LinkedIn for B2B credibility
- [ ] P1 **Organizer feedback loop:**
  - Monthly 15-minute call with top 10 most active organizers
  - "What's working? What's missing?" — product input
  - Build relationship -> becomes case study / testimonial

## Phase 4 — Optimization & Scaling (Month 2-3)

### 4.1 Channel Performance Review

- [ ] P0 **Weekly metrics review:**
  - Cost per install (CPI) per channel
  - Activation rate per acquisition source
  - D7 retention per acquisition source
  - Venue claim rate (B2B funnel)
- [ ] P0 **Double down on what works:**
  - If Instagram CPI < 3 PLN with good retention: increase budget
  - If SEO drives quality traffic: increase content production
  - If university channels have high activation: expand to more universities
  - Kill channels with CPI > 8 PLN or D7 retention < 15%

### 4.2 Conversion Optimization

- [ ] P1 **App Store listing A/B test:**
  - Test different screenshots (map-first vs event-first)
  - Test different subtitles
  - Test different app preview videos
- [ ] P1 **Web B2C -> App conversion:**
  - Optimize smart banner copy and placement
  - Track web-to-app conversion rate
  - Test different CTAs ("Download the app" vs "Follow this venue in the app")
- [ ] P1 **Venue claim funnel optimization:**
  - Track drop-off: landing page -> start claim -> complete claim -> first event published
  - Reduce friction at highest drop-off point
  - A/B test outreach email subject lines

### 4.3 Partnerships & Cross-Promotion

- [ ] P1 **Event ticketing platforms:**
  - Reach out to eBilet, Going, Bilety24 for data partnership
  - "We drive traffic to your ticket links" — mutual benefit
- [ ] P1 **City portals:**
  - Official city event portals (poznan.pl/events, etc.)
  - Cross-link or data sharing agreement
- [ ] P1 **Student organizations:**
  - NZS (student government), ESN (Erasmus network), AIESEC
  - Event co-promotion (their events appear on our map)
- [ ] P2 **Influencer micro-partnerships:**
  - Local lifestyle influencers (5-30K followers) in each city
  - Barter: featured profile on app in exchange for Instagram story/post
  - Budget: 0 PLN (barter only) or 200-500 PLN/post for key influencers

### 4.4 Localized Growth Tactics (Poland-Specific)

- [ ] P0 **Leverage WhatsApp dominance:**
  - "Share event via WhatsApp" as primary share option
  - Pre-filled message with event details + deep link
- [ ] P1 **Leverage Facebook Groups:**
  - Poland has highly active local Facebook groups ("Wydarzenia w [City]", "Co robic w [City]")
  - Engage organically (answer "what to do this weekend?" questions with EventApp links)
  - Do not spam — provide genuine value
- [ ] P1 **Student event calendar integration:**
  - Partner with university event organizers
  - Aggregate university events into the map (education category)
- [ ] P1 **Seasonal campaigns:**
  - Summer: outdoor events, festivals, food trucks
  - Winter: Christmas markets, indoor concerts, theater season
  - "Juwenalia" (student festivals — May): massive user acquisition opportunity

## Anti-Patterns (What NOT to Do)

| Don't | Why |
|-------|-----|
| Don't spend big on paid ads before product-market fit | Burning budget on users who won't retain is waste |
| Don't launch in all 7 cities simultaneously at full intensity | Focus on Poznan first, validate, then expand |
| Don't over-invest in brand before product works | Brand doesn't matter if the map is empty |
| Don't promise features that aren't built | Erodes trust with early adopters |
| Don't ignore supply-side (venues) for demand-side (users) | Empty map = instant uninstall |
| Don't use generic "Download our app" messaging | Always lead with user value: "Find events near you tonight" |
| Don't rely on a single channel | Diversify early, then optimize |
| Don't neglect organizer retention | A churned venue = lost events = lost users |
